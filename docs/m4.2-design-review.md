# M4.2 — member design slice

Implemented on `m4/design-members`, based on main after PR #14. This is the first bounded design slice, not acceptance of the whole M4.2 milestone.

## Agreed scope and behaviour

Preserve the cream, green and amber identity and large page-title treatment. Give the member directory, assignment rows and vote history more room, readable hierarchy and mobile stacking. Add one vote-choice chart using the existing M3 summary. Search still submits `q` and paging preserves it; profile filters still use `voteChoice` and `votesPage`. Filtering changes the history rows and matching total, never the chart's full-snapshot denominator. Source links, import time, missing rows and vote-specific absence wording remain visible.

Inspection found page styles in App's encapsulated stylesheet: routed child templates did not receive them. Move shared styles to the global stylesheet; retain the shell's host styling. This also restores existing title, panel and list styling on vote/report routes. No API, ingestion or data calculation changes.

## Chart definition

Each horizontal bar represents the API's exact source-value count. Width = `count / recordedEvents * 100`, where `recordedEvents` includes all of the person's rows in the latest completed session snapshot. Width is a visual scale, not a published participation rate. Exact counts, total and session are visible. All values returned by the source remain visible, including unexpected strings and an empty value labelled “Okänt källvärde”. A zero-row summary displays an explicit empty message, with no bars. Missing person rows never become Frånvarande. See the [methodology and source-linked worked example](data-methodology.md#m3-member-vote-choice-summary-202526).

The chart is semantic HTML: a named figure and labelled list with exact text counts. Decorative bars are hidden from assistive technology. Colour is supplementary, with no political/party colour coding. It needs no external chart package and renders in SSR.
