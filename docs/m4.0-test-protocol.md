# M4.0 deployment test protocol

**Gate status: NOT RUN.** Complete this short protocol on the staging host after deploying M4.0. Every row is mandatory and must be PASS with evidence before the next feature or M4 implementation slice begins. Fixes within M4.0 can continue. A source outage or inaccessible host is BLOCKED, not a pass. CI alone does not establish staging acceptance.

Record: tested commit/image tags and IDs; host/architecture; Docker/Compose versions; staging URL; tester; date/time with timezone; CI run links; completed import run IDs/source hashes. Keep secrets and raw personal-data dumps out of the evidence. Add result/evidence to this table in an acceptance commit or link an issue containing the completed table for that exact deployed commit.

| Check | Expected result / evidence to record | Result |
| --- | --- | --- |
| 1. Build and empty startup | Both CI workflows green for the tested commit; host builds all four images; fresh isolated DB migrates, second migration succeeds; health and `smoke-deployment.mjs --empty` pass. Record versions and image IDs. | NOT RUN |
| 2. HTTPS and browser | Smoke script passes through the real HTTPS hostname. Load `/`, `/voteringar`, `/arenden` directly and refresh deep links; assets load, hydration/navigation/search work, no browser errors. Check keyboard focus and narrow-screen use. | NOT RUN |
| 3. Real imports | Members, full 2025/26 vote archive and decided-report catalog complete; TU8 and a bounded status batch complete. Counts reconcile with those source snapshots. Record run IDs, hashes, counts and job exits; partial status coverage remains visible. | NOT RUN |
| 4. Source-linked trail | Open a member → a recorded vote → matching report/point → original source. TU8 displays all source points, including `acklamation`, with local vote links only for matching document/point/vote IDs. Attribution, source URLs and import times are visible. Record selected IDs. | NOT RUN |
| 5. Summary and filters | Member choice counts sum to all source rows for that ID; filtering/paging changes the list but keeps the denominator. Missing records are not counted as Frånvarande. Decision-method counts sum to imported catalog points; excluded reports are shown. Reconcile one example with source and document the numbers. | NOT RUN |
| 6. Failure and recovery | Stop API: web health 503, API proxy 502 with bounded generic response; restore and smoke passes. Deliberately fail the staging member job using the runbook's unreachable source URL: nonzero exit, previous completed run and public counts unchanged. Record before/after IDs and response codes. | NOT RUN |
| 7. Persistence and correction | Restart DB/API/web without deleting the volume; completed run IDs/data persist. Re-fetch TU8: the latest completed version is served and old points are not double-counted. Record before/after run IDs, counts and any upstream changes. | NOT RUN |

**Decision:** NOT RUN. Once all rows pass, record “M4.0 accepted”, the tested commit, tester and acceptance timestamp. A later deployment does not inherit acceptance if its image/configuration changes materially; rerun affected checks. Full backup/restore, scheduling/alerts and public-release review remain separate M4 gates.
